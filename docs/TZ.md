# Техническое задание: «Transcriber» — десктоп-приложение для транскрибации на Whisper

Версия: 0.2 (решения по открытым вопросам приняты)
Дата: 2026-10-12

## 1. Цель

Офлайн-приложение под Windows 10/11 x64, которое превращает русскую речь из аудио
и видео в субтитры SRT — в том виде, в котором их выдаёт Whisper. Распознавание идёт локально на видеокарте NVIDIA RTX 4060 (8 ГБ VRAM)
самой точной моделью Whisper, которая в неё помещается. Файлы никуда не отправляются.

## 2. Целевой пользователь и сценарии

Пользователь — человек, которому нужно расшифровать интервью, встречи, лекции,
подкасты или сделать субтитры к видео.

Основные сценарии:

1. **Файл → SRT.** Перетащил аудио или видео → нажал «Старт» → видит текст, который
   появляется по мере распознавания → рядом с исходником появляется `имя.srt`.
2. **Правка.** Открыл результат → поправил ошибки в тексте сегментов → сохранил SRT.
3. **Пакетная обработка.** Добавил папку с 20 файлами → они встают в очередь →
   приложение обрабатывает их по одному и складывает SRT рядом с исходниками
   или в указанную папку.

Язык записей — только русский. Разделение по спикерам не нужно.

## 3. Выбор модели под RTX 4060

| Модель | Параметры | VRAM (fp16, beam 5) | Точность | Скорость на 4060* |
|---|---|---|---|---|
| **large-v3** (по умолчанию, «Максимальное качество») | 1550M | ≈ 4.5–5 ГБ | лучшая | ≈ 8–12× реального времени |
| **large-v3-turbo** («Быстрый») | 809M | ≈ 2.5–3 ГБ | чуть ниже large-v3 | ≈ 30–50× |
| medium / small | — | < 2 ГБ | заметно ниже | — |

\* ориентиры, уточняются бенчмарком на целевой машине (этап 6).

Решение:

- Движок — **faster-whisper** (CTranslate2). На GPU он в 2–4 раза быстрее
  оригинального openai-whisper при той же точности и тратит меньше памяти.
- Модель по умолчанию — **large-v3, `compute_type=float16`**. Она целиком помещается
  в 8 ГБ с запасом под ОС и браузер.
- Если не хватает памяти (CUDA OOM) — автоматический откат на `int8_float16`
  (≈ 3 ГБ, потеря точности на уровне погрешности).
- Режим «Быстрый» — **large-v3-turbo** с батчевым инференсом (`BatchedInferencePipeline`).
- Без NVIDIA GPU приложение работает на CPU (`int8`) и предупреждает, что это медленно.

## 4. Функциональные требования

### 4.1 MVP (версия 1.0)

| № | Требование |
|---|---|
| F1 | Добавление файлов перетаскиванием, через диалог и целой папкой. Форматы: mp3, wav, m4a, flac, ogg, opus, aac, wma, mp4, mkv, mov, avi, webm. |
| F2 | Очередь заданий: порядок, статус (ожидает / идёт / готово / ошибка / отменено), отмена, повтор. Одновременно на GPU выполняется одно задание. |
| F3 | Язык зафиксирован: русский (`language="ru"`, без автоопределения — быстрее и без ошибок определения). Настройки задания: качество (Максимальное / Быстрое), начальная подсказка (`initial_prompt`) для терминов и имён. |
| F4 | Фильтр тишины (Silero VAD, встроен в faster-whisper), включён по умолчанию. Убирает галлюцинации на паузах. |
| F5 | Прогресс в процентах и оценка оставшегося времени. Распознанные сегменты появляются в интерфейсе сразу. |
| F6 | Редактор результата: список сегментов с таймкодами, правка текста, поиск по тексту, клик по сегменту проигрывает этот кусок. |
| F7 | Результат — SRT: сегменты Whisper как есть, без пересборки. По умолчанию сохраняется рядом с исходным файлом. Дополнительно — «Сохранить как TXT» (чистый текст). |
| F8 | История: все расшифровки сохраняются локально, их можно открыть, переименовать, удалить. |
| F9 | Первый запуск: приложение скачивает библиотеки NVIDIA CUDA (cuBLAS и cuDNN с PyPI, 1,2 ГБ, с проверкой SHA-256; только если есть видеокарта NVIDIA) и выбранную модель (≈ 3 ГБ для large-v3), с прогрессом и повтором при обрыве. |
| F10 | Экран «Система»: обнаруженная видеокарта, объём VRAM, версия CUDA, выбранный `compute_type`. |
| F11 | Таймкоды по словам (`word_timestamps`) — для точных субтитров. |

### 4.2 Вне MVP (версия 1.x–2.0)

- Запись с микрофона и потоковая транскрибация в реальном времени.
- Сводка/конспект расшифровки через LLM.
- Горячие папки (автоматическая обработка новых файлов).

## 5. Нефункциональные требования

| № | Требование |
|---|---|
| N1 | Полностью офлайн после скачивания модели. Никакой телеметрии. |
| N2 | Скорость large-v3 на RTX 4060: не хуже 8× реального времени (час аудио ≤ 7,5 мин). Turbo — не хуже 25×. |
| N3 | Пиковая VRAM в режиме по умолчанию ≤ 6 ГБ. |
| N4 | Интерфейс не подвисает во время распознавания: движок работает в отдельном процессе. |
| N5 | Падение движка не роняет интерфейс: он показывает ошибку и перезапускает движок. |
| N6 | Установщик для Windows (NSIS, `.exe`) без подписи кодом: при первом запуске SmartScreen покажет предупреждение («Подробнее → Выполнить в любом случае»). Модели и библиотеки CUDA не входят в установщик (у NSIS предел 2 ГБ) и скачиваются при первом запуске. |
| N7 | Интерфейс только на русском. |
| N8 | Ядро движка покрыто юнит-тестами; тесты проходят без GPU. |

## 6. Архитектура

```
┌───────────────────────────── Windows-приложение ─────────────────────────────┐
│                                                                              │
│  UI: React + TypeScript + Vite + Tailwind      (дизайн — плагин taste)       │
│        │  invoke / events                                                    │
│  Оболочка: Tauri 2 (Rust)                                                    │
│        │  stdin/stdout, JSON Lines                                           │
│  Движок: Python 3.11 sidecar  ── faster-whisper ── CTranslate2 ── CUDA 12    │
│          (упакован PyInstaller)                                cuDNN 9       │
└──────────────────────────────────────────────────────────────────────────────┘
```

Почему так:

- **Tauri вместо Electron** — установщик на порядок меньше, меньше памяти.
  UI при этом — обычный веб-стек, с которым работает плагин taste.
- **Python-движок в отдельном процессе** — у faster-whisper самая зрелая
  экосистема (VAD, таймкоды слов, батчинг). Отдельный процесс даёт N4 и N5.
- **Протокол JSON Lines по stdio** — не нужен сетевой порт, нет конфликтов
  с файрволом и антивирусом.

### 6.1 Протокол «оболочка ↔ движок»

Одно JSON-сообщение на строку.

Запрос: `{"id": 1, "method": "transcribe.start", "params": {...}}`
Ответ: `{"id": 1, "result": {...}}` или `{"id": 1, "error": {"code": "...", "message": "..."}}`
Событие: `{"event": "job.segment", "data": {...}}`

| Метод | Назначение |
|---|---|
| `system.info` | GPU, VRAM, рекомендуемая модель, цепочка `compute_type`, версия движка, `cuda_runtime` (ready / missing / not_needed) |
| `runtime.download` | скачать библиотеки CUDA (события `runtime.progress`, `runtime.done`, `runtime.error`) |
| `models.list` | каталог моделей и статус (скачана / нет, рекомендована) |
| `models.download` | скачать модель в фоне (события `model.*`) |
| `transcribe.start` | поставить файл в очередь (`path`, `options`, `srt_path` — куда движок сам сохранит SRT по завершении), вернуть `job_id` |
| `transcribe.cancel` | отменить задание (ожидающее или текущее) |
| `export` | сохранить (возможно, отредактированную) расшифровку в SRT или TXT |
| `shutdown` | корректно завершить движок |

| Событие | Данные |
|---|---|
| `job.status` | `job_id`, `path`, `status` (queued/running/done/error/cancelled), `error` при ошибке |
| `job.progress` | `job_id`, `done`, `total` (секунды аудио), `fraction` 0..1 |
| `job.segment` | `job_id`, `segment` (start, end, text, words) |
| `job.reset` | `job_id`, `compute_type` — не хватило VRAM, задание перезапущено с более лёгкой точностью; UI очищает сегменты |
| `job.done` | `job_id`, `transcript` (language, duration, segments), `srt_path` |
| `model.progress` | `model`, `downloaded`, `total` (байты) |
| `model.done` / `model.error` | `model`, `error` |

Коды ошибок: `parse_error`, `invalid_request`, `method_not_found`, `invalid_params`,
`not_found`, `cuda_missing`, `internal_error`.

### 6.2 Хранение данных

- Модели: `%LOCALAPPDATA%\Transcriber\models\`
- История и настройки: `%APPDATA%\Transcriber\` (SQLite для истории, JSON для настроек)

## 8. Процесс разработки

- Методология — плагин **Superpowers**: brainstorming → это ТЗ → план по этапам
  (`docs/plans/`) → разработка через тесты (TDD) → проверка перед завершением
  каждого этапа → код-ревью.
- Дизайн интерфейса — плагин **taste**: дизайн-система (цвета, типографика,
  компоненты) и экраны делаются им на этапе 4, до вёрстки.

## 9. Этапы

| Этап | Результат | Критерий готовности |
|---|---|---|
| 1. Ядро движка | Python-пакет: форматы экспорта, каталог моделей, выбор `compute_type`, обёртка над faster-whisper, очередь заданий, stdio-сервер | `pytest` зелёный, CLI транскрибирует файл |
| 2. Упаковка движка | PyInstaller-сборка под Windows с CUDA-библиотеками | `engine.exe` запускается на чистой Windows с RTX 4060 |
| 3. Оболочка Tauri | Запуск sidecar, мост команд и событий, перезапуск при падении | UI получает события `job.*` |
| 4. Дизайн (taste) | Дизайн-система и макеты экранов: Очередь, Редактор, История, Модели, Настройки | Макеты согласованы |
| 5. UI | Вёрстка экранов по макетам | Все сценарии раздела 2 проходятся руками |
| 6. Бенчмарк и полировка | Замеры на 4060, подбор `beam_size`/батча, обработка OOM | Выполнены N2 и N3 |
| 7. Релиз | NSIS-установщик, CI | Установщик ставится и работает на чистой машине |

## 10. Риски

| Риск | Что делаем |
|---|---|
| large-v3 иногда галлюцинирует на тишине и музыке | VAD по умолчанию, `condition_on_previous_text=False`, порог `no_speech_threshold` |
| Конфликт версий CUDA/cuDNN у пользователя | Скачиваем закреплённые версии cuBLAS 12.9 и cuDNN 9.27 в свою папку `%LOCALAPPDATA%\Transcriber\cuda`, не полагаемся на системные |
| CUDA-библиотеки (~1,6 ГБ) не помещаются в NSIS-установщик вместе с движком | Не кладём их в установщик, скачиваем при первом запуске с проверкой SHA-256; `cudnn_adv` (271 МБ) не нужен и не скачивается |
| Нехватка VRAM, если параллельно запущены игры или браузер | Откат на `int8_float16`, понятное сообщение |
