# Этап 1: ядро движка — план реализации

Цель: Python-пакет `transcriber_engine`, который принимает команды по stdio
(JSON Lines), ставит файлы в очередь и транскрибирует их через faster-whisper,
отправляя события прогресса. См. ТЗ, разделы 3 и 6.

Принцип: каждый модуль сначала покрывается тестами. faster-whisper в тестах
подменяется фейком, поэтому тесты не требуют GPU и скачивания модели.

## Задачи

1. **Каркас пакета** — `engine/pyproject.toml`, `src/`-layout, pytest.
2. **`formats.py`** — форматирование таймкодов; экспорт сегментов в TXT, SRT, VTT, JSON.
   Тесты: граничные значения таймкодов (0, >1 часа, округление миллисекунд),
   пустой список сегментов, многострочный текст.
3. **`models.py`** — каталог моделей (large-v3, large-v3-turbo, medium, small),
   выбор `compute_type` по устройству и VRAM, цепочка отката при OOM.
   Тесты: 8 ГБ → `float16`; CPU → `int8`; мало VRAM → `int8_float16`.
4. **`hardware.py`** — определение CUDA-устройств через CTranslate2 и VRAM через
   `nvidia-smi`. Тесты: разбор вывода `nvidia-smi`, отсутствие утилиты.
5. **`protocol.py`** — разбор и сериализация сообщений, коды ошибок.
   Тесты: корректный запрос, битый JSON, нет `method`, ответ, событие.
6. **`transcriber.py`** — обёртка над `WhisperModel`: загрузка с откатом при OOM,
   итерация по сегментам с колбэками прогресса и отменой.
   Тесты с фейковой моделью: прогресс монотонный, отмена прерывает, OOM → откат.
7. **`jobs.py`** — очередь в фоновом потоке, статусы, отмена ожидающих и текущего.
   Тесты: порядок FIFO, отмена ожидающего, ошибка задания не останавливает очередь.
8. **`server.py` + `__main__.py`** — диспетчер методов из ТЗ 6.1, потокобезопасная
   запись в stdout. Тесты: `system.info`, `transcribe.start` → события
   `job.status`/`job.segment`/`job.done`, неизвестный метод → ошибка.
9. **CLI** — `python -m transcriber_engine transcribe файл --format srt` для ручной проверки.
10. **Проверка** — `pytest`; ручной прогон на модели `tiny` на CPU.
