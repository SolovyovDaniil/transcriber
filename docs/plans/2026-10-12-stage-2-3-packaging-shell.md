# Этапы 2–3: сборка движка и оболочка Tauri — что сделано

## Этап 2 — движок в `.exe`

- `engine/packaging/engine.spec` — PyInstaller, одна папка. На Windows DLL cuBLAS и
  cuDNN 9 из pip-пакетов `nvidia-*-cu12` кладутся в `_internal/`.
- `runtime.setup_dll_search_path()` при старте добавляет эти папки в путь поиска DLL
  (ctranslate2 подгружает cuBLAS/cuDNN по имени, лениво).
- CI (`engine.yml`): тесты на Windows и Ubuntu, сборка на Windows, проверка наличия DLL
  и модели VAD, смоук-тест протокола, артефакт `transcriber-engine-windows`.

## Этап 3 — оболочка

- `app/src-tauri/src/router.rs` — id запросов, сопоставление ответов, разбор строк протокола.
- `app/src-tauri/src/engine.rs` — запуск движка без окна консоли, чтение stdout/stderr
  в потоках, события в UI (`engine://event`, `engine://status`), перезапуск при падении
  (не больше 3 раз за минуту, потом статус `failed` с хвостом stderr), корректное
  завершение при выходе из приложения.
- Порядок поиска движка: `TRANSCRIBER_ENGINE_CMD` → `engine/.venv` (только debug) →
  `resources/engine/transcriber-engine.exe`.
- UI: типизированный клиент (`src/engine`), состояние очереди только из событий движка
  (`src/state/jobs.ts`), рабочий экран без дизайна: выбор модели, скачивание, добавление
  файлов диалогом и перетаскиванием, очередь с прогрессом и отменой, текст по мере
  распознавания. SRT сохраняется рядом с исходником самим движком (`srt_path`).
- CI (`app.yml`): `tsc`, Vitest, `cargo test`; на Windows — сборка движка и NSIS-установщика.

## Проверено

- Тесты: движок 77, Rust 8 (включая реальный дочерний процесс: ответы, события, падение,
  перезапуск, отказ после повторных падений), Vitest 15.
- Приложение запущено под Xvfb: оно само поднимает движок и показывает данные из `system.info`
  и `models.list`.

## Не проверено (нужна машина с RTX 4060)

- Скачивание модели и распознавание на GPU — в этой среде Hugging Face закрыт сетевой политикой.
- Установщик на чистой Windows.
